# Инвентарь офиса — сервер на Bun

Серверная часть приложения учёта офисного инвентаря, переписанная с Python/Flask на
**[Bun](https://bun.sh)** + **[Elysia](https://elysiajs.com)** + **SQLite** (`bun:sqlite`).

Это порт исходного `app.py` (Flask) с улучшениями: REST API, TypeScript, фильтрация/
сортировка/пагинация на уровне SQL, валидация запросов, автодокументация Swagger.

> **Примечание:** статику отдаёт собственный маршрут (через `Bun.file`), а не
> `@elysiajs/static` — в Elysia 1.4 плагин конфликтует с response-валидацией для
> файловых ответов. Встроенный `Bun.file` быстрее и не имеет этой проблемы.

> Оригинальные Python-файлы (`app.py`, `requirements.txt`, `templates/`) сохранены
> в корне репозитория как референс.

## Возможности

- 📦 CRUD товаров (создание, чтение, обновление, удаление)
- 🔍 Фильтрация по категории, местоположению, минимальному количеству, поиск по тексту (полнотекстовый индекс FTS5, регистронезависимо для кириллицы)
- ↕️ Сортировка по всем полям
- 📄 Пагинация
- 📊 Статистика (всего позиций/единиц, разбивка по категориям)
- 🔐 Регистрация и вход (cookie-сессии, пароли — argon2id)
- 👥 Роли пользователей (admin / editor / viewer) и админка управления
- 📚 Автодокументация API (Swagger UI)
- ✅ Валидация входных данных (TypeBox)

## Требования

- [Bun](https://bun.sh) ≥ 1.1.0

### Установка Bun

**Windows** (PowerShell от имени администратора):

```powershell
powershell -c "irm bun.sh/install.ps1 | iex"
```

Либо через npm (если установлен Node.js): `npm install -g bun`.

> После установки проверьте: `bun --version`. Если команда не найдена — добавьте
> папку Bun в PATH. На Windows:
> ```powershell
> [Environment]::SetEnvironmentVariable("Path", "$env:Path;$env:USERPROFILE\.bun\bin", "User")
> ```
> (применится в новых окнах терминала).

## Первый запуск

1. Установите зависимости (в корне проекта):

   ```bash
   bun install
   ```

2. Создайте файл `.env` из шаблона и при необходимости отредактируйте
   (хост, порт, секрет сессии, пароль администратора):

   ```bash
   cp .env.example .env      # Windows (PowerShell): copy .env.example .env
   ```

3. Задайте пароль первого администратора в `.env`:

   ```bash
   ADMIN_USERNAME=admin
   ADMIN_PASSWORD=<придумайте надёжный пароль>
   ```

   > ⚠️ В production `ADMIN_PASSWORD` **обязателен** — без него сервер не запустится.
   > В development, если оставить пустым, пароль сгенерируется случайно и выведется
   > в консоль при первом старте.

4. Запустите сервер (см. раздел [Управление сервером](#управление-сервером)).

При первом старте база данных создаётся автоматически и наполняется
10 тестовыми позициями (если пуста). Если пользователей ещё нет, автоматически
создаётся администратор — логин берётся из `ADMIN_USERNAME` (по умолчанию `admin`),
пароль — из `ADMIN_PASSWORD`.

> ⚠️ Смените пароль администратора после первого входа!

Адреса (после запуска):

- **Сайт:** http://127.0.0.1:3000
- **API:** http://127.0.0.1:3000/api/items
- **Swagger:** http://127.0.0.1:3000/swagger
- **Healthcheck:** http://127.0.0.1:3000/health

## Управление сервером

Скрипты определены в `package.json` (`scripts`). Команды выполняются **в корне
проекта**.

### Запуск

```bash
bun run dev      # разработка: авто-перезагрузка при изменении файлов (--watch)
# или
bun run start    # обычный запуск без авто-перезагрузки
```

Сервер запускается на переднем плане (логи идут в терминал). Оставьте окно
терминала открытым, пока сервер нужен.

### Перезагрузка

- **В режиме `dev`** перезагрузка **автоматическая**: сохраните любой файл в `src/`
  или `public/` — `--watch` перезапустит сервер за доли секунды.
- **В режиме `start`** (или если нужно перезапустить принудительно): остановите
  сервер (см. ниже) и запустите снова.

### Остановка

- **Если сервер запущен в активном терминале** — нажмите `Ctrl+C`.
- **Если терминал закрыт / сервер запущен в фоне** — найдите процесс по порту
  и завершите его:

  **Windows (PowerShell):**
  ```powershell
  # найти PID процесса на порту 3000
  Get-NetTCPConnection -LocalPort 3000 | Select-Object OwningProcess
  # остановить по PID (замените <PID>)
  Stop-Process -Id <PID> -Force
  ```

  **Windows (cmd / Git Bash):**
  ```bash
  netstat -ano | findstr :3000          # второй столбец справа — это PID
  taskkill //PID <PID> //F
  ```

  **Linux / macOS:**
  ```bash
  lsof -i :3000                        # найти PID
  kill <PID>                           # или: kill -9 <PID>
  ```

### Доступ из локальной сети (с телефона / другого ПК)

По умолчанию сервер слушает `127.0.0.1` (только этот компьютер). Чтобы открыть
его для других устройств в сети:

1. В `.env` укажите `HOST=0.0.0.0` и перезапустите сервер.
2. Разрешите входящие подключения на порт 3000 в брандмауэре.
   **Windows (запуск от имени администратора):**
   ```powershell
   netsh advfirewall firewall add rule name="Inventory API 3000" dir=in action=allow protocol=TCP localport=3000
   ```
3. Узна́йте IP машины (`ipconfig` → «IPv4-адрес», например `192.168.1.50`) и
   откройте на другом устройстве: `http://<IP>:3000`.
   Оба устройства должны быть в одной сети.

> ⚠️ При `HOST=0.0.0.0` сервер виден всем в сети (без HTTPS). Не оставляйте так
> в публичной сети и смените дефолтный пароль администратора.


## Конфигурация

Через файл `.env` (скопируйте `.env.example`):

| Переменная         | По умолчанию          | Описание                                                  |
|--------------------|-----------------------|-----------------------------------------------------------|
| `PORT`             | `3000`                | Порт HTTP-сервера                                         |
| `HOST`             | `127.0.0.1`           | Хост привязки                                             |
| `DB_PATH`          | `data/database.db`    | Путь к файлу SQLite                                       |
| `CORS_ORIGIN`      | `*`                   | Разрешённые источники (через запятую)                     |
| `API_PREFIX`       | `/api`                | Префикс REST API                                          |
| `SESSION_SECRET`   | *(пусто)*             | Секрет подписи cookie-сессий. **В prod обязателен.**      |
| `SESSION_TTL_HOURS`| `12`                  | Время жизни сессии в часах                                |
| `NODE_ENV`         | `development`         | `production` включает HTTPS-only cookie и требование секрета |

## REST API

| Метод   | Путь                       | Описание                                        |
|---------|----------------------------|-------------------------------------------------|
| `GET`   | `/api/items`               | Список (фильтры, сортировка, пагинация, стат.) |
| `GET`   | `/api/items/:id`           | Один товар                                      |
| `POST`  | `/api/items`               | Создать                                         |
| `PUT`   | `/api/items/:id`           | Обновить                                        |
| `DELETE`| `/api/items/:id`           | Удалить                                         |
| `GET`   | `/api/stats`               | Статистика                                      |
| `GET`   | `/api/categories`          | Уникальные категории                            |
| `GET`   | `/api/locations`           | Уникальные местоположения                       |

### Параметры запроса `GET /api/items`

`page`, `per_page`, `category`, `location`, `min_quantity`, `search`, `sort`, `order` (`asc`/`desc`).

`sort` ∈ `id | name | category | quantity | location | date_added`.

Пример:
```
GET /api/items?category=Техника&sort=name&order=asc&page=1&per_page=10
```

## Аутентификация и роли

Вход — через cookie-сессии (токен подписан HMAC-SHA256, пароли хранятся как argon2id).
Сайт закрыт за входом: без сессии доступен только экран входа/регистрации.

| Роль     | Просмотр | Создание/ред./удал. товаров | Управление пользователями |
|----------|:--------:|:---------------------------:|:-------------------------:|
| `viewer` |    ✅    |             ❌               |            ❌              |
| `editor` |    ✅    |             ✅               |            ❌              |
| `admin`  |    ✅    |             ✅               |            ✅              |

- Самостоятельная регистрация открыта: новый пользователь получает роль `viewer`
  и статус `pending` — **вход запрещён, пока админ не подтвердит** учётную запись.
- Админ меняет роли, подтверждает и удаляет пользователей в разделе **«Админка»** (`/#/admin`).
- Защита: нельзя удалить/понизить себя и последнего администратора.

### Эндпоинты аутентификации

| Метод  | Путь                  | Доступ    | Описание                                        |
|--------|-----------------------|-----------|-------------------------------------------------|
| `POST` | `/api/auth/register`  | публичный | Регистрация (роль `viewer`, статус `pending`)   |
| `POST` | `/api/auth/login`     | публичный | Вход, установка сессионной cookie               |
| `POST` | `/api/auth/logout`    | публичный | Выход, очистка cookie                           |
| `GET`  | `/api/auth/me`        | по cookie | Текущий пользователь или `null`                 |

### Эндпоинты администрирования (только `admin`)

| Метод   | Путь                          | Описание                                        |
|---------|-------------------------------|-------------------------------------------------|
| `GET`   | `/api/admin/users`            | Список пользователей                            |
| `POST`  | `/api/admin/users`            | Создать пользователя с ролью (сразу `active`)   |
| `POST`  | `/api/admin/users/:id/approve`| Подтвердить учётную запись (`pending` → `active`)|
| `PUT`   | `/api/admin/users/:id`        | Изменить роль                                   |
| `DELETE`| `/api/admin/users/:id`        | Удалить пользователя                            |
